## 0. 十条铁律（先看这个）

| # | 铁律 | 违反后果 |
|---|---|---|
| 1 | **条件渲染分支内的 ref，一律用 state 化 callback ref**（`const [el, setEl] = useState(null)` + `ref={setEl}` + effect 依赖 `[el]`） | `useEffect([])` 在元素不存在时跑一次即失效，observer / 图表实例永不挂载 |
| 2 | **图表容器必须常驻渲染**，loading / empty 用绝对定位覆盖层，不要 `?:` 分支切换 | 容器出现后 init effect 不重跑 → 画布空白 |
| 3 | **ECharts 的 init 与 setOption 写进同一个 effect**，init 前清 `_echarts_instance_` 残留标记 | 切走再切回时 canvas = 0 |
| 4 | **SVG 文字不要放外层 HTML 覆盖层**，要写进 SVG 内部 `<text>` | 两套坐标系，响应式缩放后文字与图形错位 |
| 5 | **SVG 内字号 = 实际字号 ÷ (viewBox 宽 / 容器实际宽)**，或直接用 ResizeObserver 做 1:1 渲染 | 12px 文字实际只显示 8px |
| 6 | **渐变必须 `gradientUnits="userSpaceOnUse"`**，水平线用 `objectBoundingBox` 会整条不渲染 | 曲线集体消失，且无任何报错 |
| 7 | **判断"数据是否拉全"不要用方向/字段齐备这类脆弱条件**，用行数阈值 + 占比阈值 | 半截数据被当完整数据展示 |
| 8 | **在线接口必须加缓存 + 失败短缓存 + 有限重试 + 旧值兜底** | 按 IP 封禁后整页空白 |
| 9 | **任何汇总口径要写清是「TOP N」还是「全市场」**，且不要用 `Math.max(0, x)` 造数据 | 少算 27.6%、出现假 0 |
| 10 | **改完必跑 `npx tsc -b --force`，并用 Playwright 实测交互路径**（不只是刷新看一眼） | 切换路径的 bug 只能靠交互复现，刷新看不出来 |

## 1. 数据源与数据正确性

### 1.1 P0 — 补拉条件过严导致"半截数据"（`backend/app/services/ext_pull.py`）

**症状**：2026-09-11 的 `ext_capital_flow` 只有 100 行（94 个 in + **6 个 out**），流出合计仅 **0.03 亿**；而正常日（09-10）是 200 行（100+100）、流出 1098 亿。前端按 `latestDate` 取数，把这张"几乎全是流入"的怪图当最新数据展示。

**根因**：原判断条件为

```python
directions = {str(r.get("direction") or "").lower() for r in rows}
if directions <= {"in", "out"} and len(directions) == 1:
    # 补拉反向（翻转东财 po 参数）
```

**只有结果完全是单一方向才补拉**。而 09-11 返回 94 in + 6 out，两个方向都有，条件不满足 → 只写了流入榜。

**修复**：改成"行数 + 方向占比"双重阈值，并按 `industry` 去重合并：

```python
minor_ratio = min(各类行数) / len(rows)
if len(rows) < 150 or minor_ratio < 0.25:
    # 触发 po 翻转补拉
```

**效果**：09-11 从 100 行 → 200 行（in 94 / out 106），流出 0.03 亿 → **1598.74 亿**，最大流出板块「电子」99.93 亿。

**避坑**：判断数据完整性时，永远优先用**可量化的规模阈值**（行数、总额量级、环比突变），而不是"字段看起来都有"。

### 1.2 P0 — 东财 push2 接口按 IP 频率封禁

**症状**：连续调试十几次后，`curl` / `python` 全部 `ConnectionError(RemoteDisconnected)` 或返回 000，**与请求参数无关**，冷却数分钟后自行恢复。

**根因**：`push2.eastmoney.com/api/qt/clist/get`（AKShare `stock_sector_fund_flow_rank` 同底层）按 IP 限流。

**避坑**：

- 在线接口**必须**：≥60s 缓存 + 失败短缓存（30s）+ 有限重试 + 旧缓存续命 / mock 兜底。
- **不要直接用 akshare 封装做在线调用**：首次请求无 timeout（静默丢包会挂死线程池）+ 内置 tqdm 翻页。行业榜 <100 行一页可取完（`pz=100, fs="m:90 t:2"`），直连 `requests` 即可。
- 排查时**别误判成 UA / 参数问题**，先停手等几分钟再试。

### 1.3 P1 — 行业层级混用导致重复计算

**症状**：同一张表里东财的一级 / 二级 / 三级行业混在一起：

- 金额完全相同的 8 组：`军工电子Ⅱ` = `军工电子Ⅲ` = 9.7761 亿、`地面兵装Ⅱ` = `地面兵装Ⅲ` = 13.5826 亿
- 名称嵌套：`通信`(44.32 亿) ⊂ `通信设备`(47.41 亿) ⊂ `其他通信设备`(1.65 亿)

**修复**：前端渲染前按「**去罗马数字后缀的名称 + 金额**」去重 → 200 行 → **182 行**（剔除 18 个重复）。

**注意（不要过度去重）**：`通信` 与 `通信设备` 金额**不同**，属东财板块体系的真实父子分类，强行合并会失真，**保留**。

### 1.5 单位与口径速查（改代码前必看）

| 字段 | 单位 | 说明 |
|---|---|---|
| `ext_capital_flow.flow_amount` | **亿元** | 东财 `f62` 原始为元，入库时 ÷1e8；前端直接显示 |
| 指数日K `amount` | **元** | 需 ÷1e8 得亿元 |
| 指数日K `volume` | 股数 | 用户口中的"成交量"若单位是亿元，实为**成交额**，别取错字段 |
| Tushare `daily.vol` | **手** | 与项目日K契约一致，**不要转换** |
| Tushare `daily.amount` | **千元** | 必须 ×1000 转元（项目契约为元）。千元是最易漏的坑 |
| Tushare `adj_factor` | 累积因子序列 | **每个交易日一个值**，非单事件比值，须按 `f(d)/f(d-1)` 还原 |

**市场成交额代表标的（勿改错）**：

| 市场 | 指数 | 原因 |
|---|---|---|
| 沪市 | `000001.SH` 上证指数 | 成分 = 全部沪市股票 |
| 深市 | `399106.SZ` **深证综指** | 成分 = 全部深市股票。**不可用 `399001.SZ` 深证成指**（仅 500 只成分股，成交额严重低估） |

实测 2026-09-10：沪 7796.73 亿 / 深 8674.75 亿 / 合计 1.65 万亿，量级正确。

### 1.6 P2 — 接口参数下限

`/api/index/daily` 的 `days` 参数**最小为 10**（传 <10 报 422 `greater_than_equal`），且是**自然日**不是交易日：`days=120` → 85 个交易日。

### 1.7 新增数据源插件（以 Tushare 为例）

**先判断：能否"通过设置页新增自定义源"解决？** 判据是协议形状，与数据内容无关：

| 维度 | 声明式 YAML 源（`GenericHTTPProvider`）要求 | Tushare 实际 |
|---|---|---|
| 请求参数 | 扁平 `{symbols, start_time, end_time}`（参数名可改，**不能嵌套**） | `{api_name, token, params:{...}}` — **必须嵌套** |
| 鉴权 | 仅 `bearer` / `header` / `query` 三种 | token 在 **body 内** |
| 响应 | `response_path` 指向**对象数组** | `{data:{fields:[...], items:[[...]]}}` 列名与二维行分离 |

三者任一不匹配 → 必须走插件（`docs/plugin-development.md` 的 `runtime` 典型场景已列出 akshare / tushare，属官方预期路径）。

**插件最小结构**（L2 二次开发：新增独立模块 + 注册表接线，**不动任何 service / API 代码**）：

```
backend/app/plugins/<name>/
├── plugin.yaml   # name / entry / check / datasets / api_key_env
├── __init__.py
├── client.py     # 只管 HTTP: 鉴权、信封解包、分页、节流
└── provider.py   # 只管契约: 单位换算、字段映射、取数模式、test_dataset
```

**注册是自动的**：`loader._load_builtin_plugins()` 扫描 `plugins/*/plugin.yaml`，调 `check` 函数通过后把 provider 塞进 `_PROVIDERS`；而 `preferences._allowed_data_providers()` = 硬编码集合 ∪ `loader.names()`。**所以设置页下拉框会自己多出一个选项，无需改 preferences.py / settings.py。**

provider 必须实现的契约（service 层按这套签名调用，缺一个就路由失败）：

| 成员 | 说明 |
|---|---|
| `name` / `builtin = True` | `builtin` 决定不可被用户在设置页编辑/删除 |
| `config.datasets` | dict 或可 `in` 判断的容器；**只放真实提供的数据集**，未声明的会自动回退现有源 |
| `iter_daily(symbols, start_time=, end_time=, asset_type=, on_chunk_done=)` | 可选但强烈建议（历史同步逐批落盘，避免全市场堆内存） |
| `get_daily(...)` | 同签名，返回 `pl.DataFrame` |
| `get_adj_factors(...)` | 返回 `symbol/trade_date/ex_factor`，见下方因子口径 |
| `test_dataset(dataset, symbols)` | 设置页「试拉测试」；`date` 必须转 ISO 字符串，否则 JSON 序列化炸 |
| `close()` | `load_all()` 重建注册表时会被调用 |
| 模块级 `availability()` | 返回 `(bool, str)`；未配置 Key 时返回 False → 插件灰显但不会启动崩溃 |
| 模块级 `probe_api_key(key)` | 声明了 `api_key_env` 就必须提供，供设置页「先探后存」 |

**除权因子的口径陷阱（最容易错）**：项目 `pipeline._apply_adj_factor` 要求的 `ex_factor` 是**单事件 pre/post 比值**（>1 表示除权），会再用 `cum_prod()` 累积。而 Tushare 给的是**累积因子序列**（每个交易日一个值）。还原公式：

```
复权价 = close(t) * f(t) 在除权日必须连续，故 f(d) / f(d_prev) = close(d_prev) / 除权参考价 = pre/post 比值
```

该推导**与因子基准无关**（前复权/后复权口径都成立），但有两个硬要求：

1. 取数窗口要**向前多取一段自然日**（当前实现 30 天），否则窗口首日的事件拿不到 `f(d_prev)`，会被静默丢弃；
2. 因子未变化的交易日**不是除权事件**，要用阈值（1e-6）过滤，否则每天都会产出一条垃圾因子。

**取数模式要按"请求数"而不是直觉选**：Tushare 单次上限 6000 行，而全市场约 5400 只 —— 按交易日取数**一天一次请求**就能拉完；按 ts_code 逐只拉全市场则是 5000+ 次。所以标的数 ≥100 走"交易日历 + 逐日"，少量标的走"逐标的"。官方也明确建议"循环日期提取全市场，不要循环 ts_code"。交易日历不可用时要有回退路径。

**失败处理**：少量请求失败只告警继续，但**失败过半必须抛错**——半截数据落库的代价比同步失败高得多（资金流向面板的教训）。

### 1.8 P1 — 非 symbol 维度的扩展表：日志刷屏 + 注册出"幽灵因子"

**现象**：每次 enriched 刷新刷 3 条告警

```
[WARNING] app.factors.ext_factors: 扩展表 ext_capital_flow 列注入失败, 跳过该表:
          unable to find column "symbol"; valid columns: ["date","industry","flow_amount","direction"]
```

**根因**：`ext_factors._select_fields()` 第一行就 `pl.col("symbol")`，而按板块聚合的表
（`ext_capital_flow` 的列是 `date/industry/flow_amount/direction`）压根没有 symbol 列 →
每次 join 抛异常 → 被上层 `except` 吞掉记 WARNING。功能上不报错，但日志污染严重。

**真正的问题不在日志**：`ext_factor_specs()` 只看**配置**不看数据 schema，于是把
`ext_ext_capital_flow_flow_amount` 注册成了一个因子 —— 它 join 不进帧，在因子库/策略/回测里
是一个**恒 null 的幽灵因子**（能选、能配，永远没值）。`ext_string_field_entries()` 同理，
会往信号条件下拉里塞进恒 null 的条件。

**修复**：新增 `is_symbol_dimension(root, cfg)` —— 用 `pl.scan_parquet().collect_schema()`
（只读 footer，不加载数据）判断有没有 symbol 列，结果按 `(mtime, size)` 签名缓存。三个入口统一过滤：

| 入口 | 非 symbol 维度时 |
|---|---|
| `attach_ext_columns` | 静默 `continue`（不再刷 WARNING） |
| `ext_factor_specs` | 整表跳过，不注册因子 |
| `ext_string_field_entries` | 不进信号条件下拉 |

**约定**：按**非标的维度**聚合的扩展表（板块 / 概念 / 地域 / 行业汇总）由看板走
`extDataRows` 直接读分区消费，**不进因子与信号通道**。新增这类表时不用改代码，
`is_symbol_dimension` 会自动识别。

**探测失败/无数据文件时保守返回 True**（按有 symbol 处理，维持既有行为），
等真正写入数据后再按真实 schema 判定。

## 2. SVG 图表（桑基图 / 自适应坐标系）

### 2.1 P0 — HTML 文字覆盖层与 SVG viewBox 坐标系错位

**症状**：文字压在条带上、行距错乱；调参三轮无效。

**根因**：文字用外层 `absolute` + 百分比定位，而 SVG 用 `viewBox` + `preserveAspectRatio="meet"` 自适应缩放。**卡片宽度 ≠ viewBox 宽度（800）时两套坐标系必然错位**，且 `meet` 还会居中留白。

**修复**：文字全部改到 SVG 内部用 `<text>` 渲染，与条带 / 曲线**共享同一坐标系**，缩放再多也不会错位。

---

### 2.2 P0 — SVG 内文字被整体缩放，字号远小于设计值

**症状**："字体太小"（实际 12px 只显示 ~8px）、"内容缩小居中、两侧大片空白"。

**根因**：viewBox 宽 800、容器实际 ~520 → 缩放比 0.65，写在 SVG 里的任何字号都被乘 0.65。

**修复**：用 `ResizeObserver` 实测容器宽度，**把 viewBox 宽直接设为实测宽度**做 1:1 渲染。

---

### 2.3 P0 — 条件渲染分支内的 ref + 空依赖 effect ⇒ observer 永不挂载

**症状**：上一节的 1:1 方案"写对了却从未生效"，`measuredW` 恒为 0，页面一直按 800 宽缩放。

**根因（React 时序坑，最常见的一个）**：

```jsx
const wrapRef = useRef(null)
useEffect(() => {                      // ← 空依赖，只在挂载时跑一次
  const el = wrapRef.current           // ← 此刻 div 还不存在（在 configured ? 分支内）
  if (!el) return                      // ← 直接 return，observer 永远挂不上
  ...
}, [])

return configured ? <div ref={wrapRef}>...</div> : <占位/>
```

**修复**：state 化 callback ref，让 effect 随元素挂载重新执行：

```jsx
const [wrapEl, setWrapEl] = useState(null)
useEffect(() => { /* observe */ }, [wrapEl])
return configured ? <div ref={setWrapEl}>...</div> : <占位 />
```

测量完成前渲染同高占位 div，避免布局跳动。

---

### 2.4 P0 — 水平曲线的渐变失效导致整条 path 不渲染

**症状**："中间的流动曲线不见了"，且**控制台无任何报错**。

**根因（SVG 规范，非浏览器 bug）**：`linearGradient` 默认 `gradientUnits="objectBoundingBox"`；当 path 是**水平线**（起终点同行，包围盒高度 = 0）时，该渐变**无效 → 整条 path 被跳过不渲染**。TOP16 曲线几乎全是水平线，于是集体消失。

**修复**：

```jsx
<linearGradient id="cap-flow-grad" gradientUnits="userSpaceOnUse"
                x1={LEFT_COL_END} y1="0" x2={RIGHT_COL_X} y2="0">
```

用**绝对坐标**锚定曲线通道两端，与包围盒无关。

---

### 2.5 P1 — 桑基连线权重公式退化，22 个板块 14 个零连线

**症状**：只有左右各前 4 个板块之间有曲线，其余 14 个板块（数字芯片设计、非银金融、医药生物…）完全没有线。

**根因**：权重 `weight = min(h_i, h_j) / maxCross` 中，最大块 `h_0` 恒 ≥ 其他块，于是

- `(0, j)` 权重 = `min(h_0, h_j)/maxCross` = **h_j / maxCross**
- `(i, 0)` 权重 = **h_i / maxCross**

**权重退化成只由单个块高度决定，与"配对"无关**；全局排序取 top16 后，连线必然全落在最大的一两个板块上。实测验证：旧算法左侧 7 个 + 右侧 7 个 = **14 个板块无线**，与用户观察完全吻合。

**修复**：改为**每板块保底连线**（`LINKS_PER_BLOCK = 2`）——每个流出板块连到权重最高的 2 个流入板块，每个流入板块也从权重最高的 2 个流出板块收线，Map 去重。结果 40 条线，**零遗漏**。

---

### 2.6 语义红线：桑基连线是**示意**，不是真实资金路径

公开数据只有「各板块净流入 / 净流出金额」，**不存在板块之间的资金流动矩阵**（没有"电子的钱流到通信设备"这种数据）。连线必须在图上标注为示意，否则极易被误读。若会造成困扰，宁可改成左右对照的条形图（纯真实数据）。

### 2.7 配色

遵循 A 股习惯：**流入 = 红（`#f87171`）/ 流出 = 绿（`#34d399`）**，新资金 = 琥珀（`#fbbf24`），离场 = 灰。写反了会被一眼看出来。

## 3. ECharts（条件视图切换 / 实例生命周期）

### 3.1 P0 — 容器条件渲染 ⇒ ECharts 永不挂载（容器在、canvas = 0）

**症状**：标题数值都出来了，但**曲线区空白**。

**根因**：曲线容器写在 `{loading ? … : empty ? … : <div ref={boxRef}/>}` 分支内，数据到达前不渲染；而 init effect 是空依赖 `[]`，容器出现后**不会重跑** → ECharts 从未 init。

**诊断方法（Playwright）**：

```js
document.querySelector('main').querySelectorAll('canvas').length  // → 0
```

**修复**：曲线容器**常驻渲染**，loading / empty 改用绝对定位覆盖层：

```jsx
<div className="relative min-h-0 flex-1">
  <div ref={setBoxEl} className="h-full w-full" />
  {(loading || empty) && <div className="absolute inset-0 …">加载中…</div>}
</div>
```

### 3.2 P0 — 切走再切回时 canvas = 0（init 与 setOption 分离 + 实例标记残留）

**症状**：首次点击进入正常；**切回指数再切回本视图时曲线空白**，刷新页面又恢复。

**根因（两个叠加）**：

1. init 依赖 `[boxEl]`、setOption 依赖 `[option]` 分属两个 effect。切走时组件 unmount → cleanup 中 `dispose()`；切回时若 React 复用同一 div 且 `option` 因数据来自缓存而未变，**两个 effect 都不重跑** → 没人重新画图。
2. `echarts.init` 对残留 `_echarts_instance_` 标记的 DOM 会返回**已 dispose 的死实例**（无 canvas），连重建机会都没有。

**修复**：init + resize + setOption 合并到**同一个 effect**，每次都校验实例并清理残留标记：

```tsx
useEffect(() => {
  const el = boxEl
  if (!el) return
  let chart = chartRef.current
  if (!chart || chart.isDisposed()) {
    const stale = echarts.getInstanceByDom(el)
    if (stale) stale.dispose()
    el.removeAttribute('_echarts_instance_')   // 关键：清残留标记
    chart = echarts.init(el, undefined, { renderer: 'canvas' })
    chartRef.current = chart
  }
  chart.resize()
  chart.setOption(option, true)
  const raf = requestAnimationFrame(() => {      // 首帧尺寸为 0 时兜底重绘
    const c = chartRef.current
    if (c && !c.isDisposed()) { c.resize(); c.setOption(option, true) }
  })
  return () => cancelAnimationFrame(raf)
}, [boxEl, option])
```

ResizeObserver 与 dispose **各自独立成 effect**，所有回调带 `isDisposed()` 防御。

**验证**：Playwright 来回切换 6 次，每次 `canvas = 1` 且画布有实际绘制内容，零 pageerror。

### 3.3 叠加序列的注意事项（沪 + 深 + 合计）

- 同量纲（都是亿元）**共用一根 Y 轴**即可，但合计线量级 ≈ 单市 2 倍，会把沪深两线压到下半区——这是同轴叠加的必然结果；用户若反馈压扁，再改双 Y 轴或把合计改柱状垫底。
- 第三条线**不要再加面积填充**（三层渐变会糊成一团），用更粗的线 + `z: 3` 置顶。
- 合计数据缺失策略：两侧都有值 → 求和；仅单侧 → 退化为该侧值（保证曲线连续）；两侧均无 → `null` + `connectNulls: true`。
- 新曲线颜色用**中性色（如紫 `#A78BFA`）**，避开涨跌红绿，防止语义混淆。
